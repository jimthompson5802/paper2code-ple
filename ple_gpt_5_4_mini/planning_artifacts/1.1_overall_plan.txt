# 2) Methodology to reproduce

## 2.1 General framework for numerical embeddings

The paper defines a per-feature embedding function:

- For each numerical feature \(x_i\), compute
  \[
  z_i = f_i(x_i) \in \mathbb{R}^{d_i}
  \]
- Important constraints:
  - Each feature is embedded **independently**
  - The same functional form is used across all features
  - Parameters are **not shared** between features
- Output usage:
  - For **MLP-like** backbones: concatenate all feature embeddings into one flat vector
  - For **Transformer-like** backbones: feed embeddings as token-like feature vectors directly

This is crucial: do **not** mix numerical features inside the embedding function itself, except where the backbone later mixes them.

---

## 2.2 Piecewise Linear Encoding (PLE)

This is one of the paper’s main contributions.

### Core idea
For each numerical feature, split its range into bins and encode a scalar value as a piecewise-linear vector over bins.

### Encoding behavior
For a feature value \(x\) and bins \(B_1,\dots,B_T\), the encoding is a vector of length \(T\). Each component is:

- 0 before the active interval
- 1 after the active interval
- linearly interpolated inside the active bin

This makes the representation:
- continuous
- ordered
- more expressive than scalar input
- still relatively interpretable

### Important implementation note
For **Transformer-based models**, PLE alone is not enough because Transformers are permutation-invariant over token order. The paper solves this by placing a **linear layer after PLE** so each feature’s bins are mapped to a trainable embedding space.

Formally:
- PLE(x) → Linear → final embedding

This is equivalent to having trainable vectors for bins and aggregating them with PLE weights.

---

## 2.3 Bin construction for PLE

The paper uses two binning strategies:

### A. Quantile-based bins
- Bins are formed using empirical quantiles of each feature on the **training split**
- Use the training set only to compute quantiles
- Remove empty bins if any

This is the unsupervised version: **PLE-q**

### B. Target-aware bins
- Bins are built using labels
- The method is analogous to **C4.5 discretization**
- Practically, for each feature, build a greedy 1D decision tree on the training data using the target
- Leaves define bins
- Also set:
  - \(b_0 = \min(x)\)
  - \(b_T = \max(x)\)

This is the supervised version: **PLE-t**

### Hyperparameters to tune
For target-aware PLE:
- maximum number of leaves
- minimum number of items per leaf
- minimum information gain required for a split

For quantile PLE:
- number of quantiles

## 2.4 Periodic activation embeddings

The paper also adapts periodic features for tabular data.

### Key design choice
Unlike some coordinate-based periodic approaches, the paper insists that each feature be embedded **separately before mixing**.

### Trainable form
- Uses trainable pre-activation coefficients
- Initialize coefficients from \( \mathcal{N}(0, \sigma) \)
- Tune:
  - \(\sigma\)
  - \(k\) (number of periodic components / embedding size factor, as described in the paper)

The exact mathematical equation is not fully visible in the provided parse, but the implementation should follow the repository/paper formula as closely as possible:
- periodic transform per feature
- trainable coefficient initialization
- feature-wise independent embedding

This module is named **Periodic** in the experiments.

## 2.5 Simple differentiable layers on top of embeddings

The paper tests whether standard layers improve embeddings:

- Linear
- ReLU
- LeakyReLU
- stacked combinations like:
  - Linear
  - Linear + ReLU
  - Linear + ReLU + Linear
  - etc.

Important naming convention from the paper:
- **L** = linear layer
- **LR** = linear layer + ReLU
- **LRLR** = linear + ReLU + linear + ReLU
- **P** = periodic base module
- **PL** = periodic + linear
- **PLR** = periodic + linear + ReLU
- **PLE q / PLE t** similarly combined with linear/relu

For Transformer models, the paper often uses a linear layer after PLE to restore a token embedding dimension.
