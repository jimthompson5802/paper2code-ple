2. EMBEDDING MODULES

A. Abstract Base Class – EmbeddingModule  
 • Define an abstract class (subclassing torch.nn.Module) with an abstract forward(x: Tensor) → Tensor method.
 • This will serve as the interface for all embedding modules.  
 • No additional public member functions should be added, so that the interface remains exactly as indicated in the design.

B. PiecewiseLinearEmbedding  
 • Purpose:  
  – Implements the Piecewise Linear Encoding (PLE) as described in Section 3.2 of the paper.
  – It maps a scalar numerical input x into a T-dimensional “PLE vector” using precomputed bin boundaries.
 • Important details:  
  – The bin boundaries (b₀, b₁, …, b_T) are computed using either a quantile-based algorithm (PLE_q) or a target-aware algorithm (PLE_t). (For this analysis, we assume that if the configuration “model.embedding.type” is set to "PLE_q", the quantile-based version is used.)
  – The method compute_bins(data: Tensor) → List[float] is provided so that given training data for a specific numerical feature, the bin thresholds can be computed using one of the two approaches. (The actual bin‐computation logic will rely on scikit‐learn’s quantile functions or a decision tree–like split for target-aware bins.)
  – The piecewise linear encoding is defined as follows (for each bin index t = 1,…,T):
   ◦ If t > 1 and x is less than b₍ₜ₋₁₎, then set eₜ = 0.
   ◦ Else if t < T and x is greater than or equal to bₜ, then set eₜ = 1.
   ◦ Otherwise, compute eₜ = (x − b₍ₜ₋₁₎)⁄(bₜ − b₍ₜ₋₁₎).  
  – Note the boundary cases: if x is less than b₀ or x is greater than or equal to b_T, the “else” branch yields e₁ < 0 or e_T ≥ 1, respectively. This is acceptable per the paper.
 • Implementation Steps:  
  1. In __init__(params: dict), read parameters such as the number of bins (from config.data.quantile_bins for quantile-based PLE) and any other necessary tuning parameters (from config.data.target_aware_params if using target-aware).  
  2. Set self.bins to None initially; it will be later computed using compute_bins(data) (this function may be called externally when training data is available).
  3. Initialize a linear layer (e.g., self.linear = nn.Linear(num_bins, embedding_dim)) where the output “embedding_dim” should ideally match the backbone’s expected input dimension. (The embedding dimension may be derived from config.model.backbone.mlph_hidden_size or an explicitly passed parameter.)
  4. In forward(x: Tensor):  
   – For each scalar x (or for a batch of shape [batch_size, 1] for a single feature), compute the vector e by applying the piecewise linear interpolation logic using the precomputed bin thresholds.
   – This step can be vectorized or implemented using a loop over batch elements.  
   – Pass the computed PLE vector (of dimension T) through self.linear to obtain the final embedding.
 • The function compute_bins(data: Tensor) → List[float] should:  
  – Accept a Tensor of training data for one feature.
  – Compute the bin thresholds (using numpy.percentile or similar) according to the selected strategy (quantile-based or target-aware).
  – Remove any trivial bins if needed.
  – Store and return the ordered list of bin boundaries.

C. PeriodicEmbedding  
 • Purpose:  
  – Implements the embedding module based on periodic functions, as described in Section 3.3.
  – It processes the scalar input x by applying a periodic transformation (e.g., sin(k · x + c)).
 • Key Points:  
  – “k” is a hyperparameter; its allowed range is provided by config.embedding.periodic.k_range. (When using hyperparameter tuning, “k” is chosen from this range.)  
  – “c” is a trainable offset (a parameter) initialized from a Gaussian distribution N(0, σ) with σ given by config.embedding.periodic.sigma.
  – It is crucial that each numerical feature is processed independently (i.e. no mixing across features until after the periodic transform).
  – Optionally, an extra differentiable linear layer may be added on top of the periodic activation to “fuse” the embedding before passing it to the backbone (as some experimental variants add this extra component).
 • Implementation Steps:  
  1. In __init__(params: dict), read the parameters “k” (or assign a default or tunable value within k_range) and “sigma.”
  2. Determine the desired output embedding dimension (for consistency with the backbone); then initialize a trainable parameter (self.c) of shape (embedding_dim,) with values drawn from N(0, sigma).  
  3. (Optional) Initialize an extra linear layer (e.g., self.linear) if a fused output is desired.
  4. In forward(x: Tensor):  
   – Expect x as a scalar or a tensor of shape [batch_size, 1].
   – Expand or broadcast x if necessary so that the operation “k * x” becomes compatible with the vector self.c.
   – Compute the periodic transform: phi = sin(k * x + self.c).  
   – (If an extra linear layer is used, return self.linear(phi); otherwise, return phi directly.)

D. LinearEmbedding  
 • Purpose:  
  – Provides a baseline embedding using a conventional bias‐incorporated linear layer.
 • Implementation Steps:  
  1. In __init__(params: dict), simply create a linear transformation: self.linear = nn.Linear(1, embedding_dim).
  2. In forward(x: Tensor):  
   – Return self.linear(x).

3. BACKBONE MODELS

A. MLP  
 • Purpose:  
  – A simple, fully connected network that takes as input the concatenated embedded features.
 • Implementation Steps:  
  1. In __init__(config: dict), read configuration values (e.g. number of layers from config.model.backbone.mlp_layers and hidden size from config.model.backbone.mlp_hidden_size).
  2. Construct a sequential network (e.g., using nn.Sequential) consisting of multiple linear layers and activation functions (ReLU is typical).  
  3. The input dimension should equal (number_of_features × embedding_dim) if embeddings for all features are concatenated.
  4. In forward(x: Tensor):  
   – Receive a 2D tensor (after concatenation) and pass it through the network.

B. ResNet  
 • Purpose:  
  – Similar to the MLP backbone but with residual (skip) connections between layers.
 • Implementation Steps:  
  1. In __init__(config: dict), define a series of residual blocks. A residual block may comprise one or more linear layers with a skip connection.
  2. Ensure that the dimensions align so that residual addition is possible.
  3. In forward(x: Tensor), sequentially apply the blocks and return the output.

C. TransformerModel  
 • Purpose:  
  – An attention‐based model (e.g., FT-Transformer) that accepts individual feature embeddings as tokens.
  – Since self-attention is invariant to token order, it is recommended to inject feature-specific information by applying an additional linear mapping after initial embeddings.
 • Implementation Steps:  
  1. In __init__(config: dict), set up a transformer encoder. This may include:  
   – A linear layer (or token embedding layer) that injects feature indexing information if using embeddings computed from PLE.  
   – Transformer encoder layers (e.g., using torch.nn.TransformerEncoderLayer and torch.nn.TransformerEncoder).
  2. In forward(x: Tensor), assume that x has shape [batch_size, num_features, embedding_dim].  
   – Optionally process each token with the extra linear layer for index injection.
   – Pass the token sequence through the transformer encoder.
   – Aggregate token outputs (for instance, via concatenation or pooling) and return the final prediction.

4. MODEL WRAPPER

• Purpose:  
 – Combine the embedding module(s) with the backbone.
• Key Aspects:  
 – The wrapper Model class should read configuration settings (from the centralized config dictionary) to decide which embedding type to create (e.g., “PLE_q”, “PLE_t”, “Periodic”, or “LR”) and which backbone to use (MLP, ResNet, or Transformer).  
 – Since each numerical feature is embedded separately and saved as a unique instance (parameters are not shared across features), the Model class may create a nn.ModuleList to store one embedding instance per feature.
 – The Model’s forward(x: Tensor) method should:  
  ◦ Split the input tensor x along its feature dimension (assume shape [batch_size, n_features]).  
  ◦ Apply the corresponding embedding module to each feature column.  
  ◦ For MLP and ResNet backbones, concatenate the resulting embeddings along the feature dimension.  
  ◦ For the Transformer backbone, stack them as tokens (resulting in shape [batch_size, n_features, embedding_dim]).  
  ◦ Pass the resulting tensor to the backbone and return its output.
• Implementation Steps:  
 1. In __init__(self, params: dict):  
  – Parse the configuration to get the number of numeric features (this may be provided or inferred).
  – For each feature, instantiate the appropriate EmbeddingModule subclass using the configuration parameters:
   • For embedding type “PLE_q” or “PLE_t”, create a new PiecewiseLinearEmbedding instance.
   • For “Periodic”, create a PeriodicEmbedding.
   • For “LR”, create a LinearEmbedding.
  – Store these in a ModuleList (e.g., self.embeddings).
  – Instantiate the chosen backbone model (e.g., if config.model.backbone.type == "MLP", create an MLP instance with the required input dimension, which should match the total concatenated embedding dimensions).
 2. In forward(x: Tensor):  
  – Assume x is of shape [batch_size, n_features]; for each feature (e.g., using a loop over the ModuleList), extract the corresponding column (reshaped as [batch_size, 1]) and compute its embedding.  
  – Depending on the backbone, either concatenate the embeddings along the feature dimension (resulting in a 2D tensor) or stack them as a 3D tensor (for Transformer, where each embedding is a “token”).
  – Pass the resulting tensor to the backbone’s forward() and return the final output.

6. SUMMARY

The “model.py” file is organized as follows:

• An abstract EmbeddingModule defines the common interface.
• The PiecewiseLinearEmbedding class implements the PLE strategy:
 – It includes a compute_bins method (to be called external to training or during model setup) that calculates bin boundaries from training data.
 – Its forward method applies the piecewise interpolation using the precomputed bins and then passes the resulting vector through a feature-specific linear layer.
• The PeriodicEmbedding class applies a periodic transformation (sin(k·x + c)) to the input and (optionally) adds a further linear layer.
• The LinearEmbedding class simply maps the scalar input to an embedding vector via a linear layer.
• The backbone models (MLP, ResNet, TransformerModel) are defined to process the final embedded representations. MLP and ResNet expect a concatenated flat vector whereas the TransformerModel expects a sequence of embeddings (with an additional token/feature indexing injection).
• Finally, the Model wrapper instantiates one embedding module per numeric feature (ensuring no parameter sharing among features) and then integrates the backbone. In its forward pass, it processes each feature via its corresponding embedding, concatenates or stacks the results as appropriate, and then passes the combined tensor to the backbone.
• All hyperparameters (such as learning rate, number of bins, sigma for periodic embedding, mlp_layers, and mlp_hidden_size) are to be sourced directly from the provided configuration (config.yaml), ensuring fidelity to the experimental design described in the paper.

This careful modular design and strict adherence to configuration settings will help guarantee that the code reproduces the experiments and methodologies described in the paper without deviations.
