Below is a comprehensive roadmap outlining how to reproduce the method described in “On Embeddings for Numerical Features in Tabular Deep Learning.” This plan details both the methodology and the experimental pipeline (datasets, preprocessing, architectures, training, hyperparameter tuning, evaluation, and ablations) so that later you can implement the code with confidence.

────────────────────────────
1. OVERVIEW & OBJECTIVES

• Goal: Implement a family of embedding modules that transform scalar (numerical) features into high-dimensional representations in order to improve tabular deep learning models.  
• Main ideas to implement:
  – An embedding “framework” where each numerical feature is embedded independently.
  – Two main embedding families:
   • Piecewise Linear Encoding (PLE): using binning methods (unsupervised quantile‐based or supervised target-aware) and then a linear fusion to produce the final embedding.
   • Periodic activation based modules: where the scalar is transformed using periodic functions with trainable parameters.
• Additionally, also implement baseline (conventional) differentiable embedding modules (e.g., a bias-free linear layer, linear plus ReLU, or “LRLR” alternatives) to compare against the new methods.
• Integrate these embeddings into several backbone architectures (MLP, ResNet, and Transformer) and compare their performance against Gradient Boosted Decision Trees (GBDT) benchmarks (e.g., CatBoost/XGBoost).

2. METHODOLOGY IMPLEMENTATION DETAILS

A. General Embedding Framework
  • For each numerical feature, design an embedding function f₍ᵢ₎(x). Each feature is processed separately (no mixing during embedding) before joining them in the main model.
  • In MLP-like architectures, concatenate all embedded vectors to create a flat input vector.
  • For Transformer-based backbones, pass each feature’s embedding as a separate “token” and (if needed) follow with an additional linear layer to encode feature indices.
  • The framework should allow plugging in different embedding “modules” for each numerical feature.

B. Implementing Piecewise Linear Encoding (PLE)
  1. Binning Strategies:
   a. Unsupervised (Quantile-based):
    – For each feature, compute empirical quantiles from the training data.
    – Remove bins with zero width.
   b. Supervised (Target-aware):
    – For each feature, perform a recursive greedy split (similar in spirit to the C4.5 discretization algorithm). Essentially, build a one-feature decision tree using the target value to decide splits.
    – Use the leaf intervals as bins.
  2. PLE Encoding Computation:
   – For each feature value x, given T bins with boundaries b₀, b₁, …, b_T, compute a T-dimensional vector as follows:
    • For bins where x is completely below the bin’s left threshold, output 1 (or reflect that the bin is “activated”).
    • For the bin where x lies between bₜ₋₁ and bₜ, compute the linear interpolation: (x – bₜ₋₁)/(bₜ – bₜ₋₁).
    • For bins above x’s current bin, output 0.
  3. Post-processing with trainable parameters:
   – Each feature’s PLE vector is then fed through one “final” linear layer: f₍ᵢ₎(x) = v₀ + Σₜ eₜ · vₜ, where eₜ are the PLE outputs and v₀, vₜ are trainable embedding parameters.
   – This has the interpretation of “fusing” the indicator/interpolated bins with separate trainable embeddings per bin.
  4. Implementation considerations:
   – Make design choices parameterized (e.g., number of bins T – to be tuned on a validation set).
   – Allow switching between quantile-based and target-aware binning.

C. Implementing Periodic Activation Embeddings
  1. Framework:
   – For each numerical feature, apply a periodic transformation. Although the paper’s Equation 2 is only briefly described, the idea is to have trainable “pre-activation” coefficients that, after being modulated (for instance, using sin() or another periodic function), produce the embedding.
  2. Key details:
   – Introduce trainable parameters cᵢ (initially drawn from N(0, σ); σ is a hyperparameter to tune) and a multiplier (k) that is either per feature (or shared) and also tuned.
   – After applying the periodic activation, as with PLE, consider coupling this module with an additional linear layer (e.g., “PLR” variant) to improve performance.
  3. Implementation considerations:
   – The choice of periodic function (sinusoidal, cosine, etc.) and how to combine with a linear map should be made consistent with the description in the paper and the modifications reported (i.e., “Periodical with linear component” has shown best efficacy).
   – Since details are a bit brief, note that this part may require checking original references (such as Li et al. [25]) or clarifying the exact formulation before final implementation.

D. Baseline (Conventional) Differentiable Embedding Modules
  – For comparison, implement “vanilla” approaches that use simple linear layers and ReLU or leaky ReLU.
  – For example, a “LR” module is just a single linear (bias-free) layer mapping the scalar value to a high-dimensional space.
  – Also consider sequential modules like “LRLR” (multiple layers) as discussed in the paper, while noting that added complexity might lead to extra computational cost.

E. Backbone Architectures
  1. MLP:
   – Implement a standard MLP for tabular data (e.g., 4 fully connected layers, each with 256 units as used in synthetic experiments).
   – Concatenate the outputs of all feature embedding modules as the input.
 2. ResNet:
   – Implement a ResNet-like model for tabular data with skip connections. Use similar dimensions and dropout settings as in the original paper.
 3. Transformer:
   – Adapt an attention-based architecture (e.g., FT-Transformer) that takes the feature embeddings as separate tokens without mixing them ahead of time.
   – Include a simple linear layer after the embedding stage if needed to add feature-index information.
   – Use hyperparameter distributions (e.g., number of layers, embedding sizes as in Table 17 of the paper) to guide tuning.

3. EXPERIMENTAL PIPELINE

A. Datasets & Data Preprocessing
  1. Datasets:
   – Reproduce experiments on the 11 public datasets described in the paper (e.g., Adult, California Housing, Otto Group Product Classification, Churn Modeling, Facebook Comments, Covertype, etc.).
   – For the synthetic “GBDT-friendly” dataset:
    • Generate 10,000 samples with 8 features sampled ~ N(0,1).
    • Produce the target using an ensemble of 16 randomly constructed decision trees (depth 6).
  2. Data Splits:
   – Split datasets into training, validation, and test sets as described in the paper.
   – Use the provided guidelines (see “Notation” in the paper): training for optimization, validation for early stopping/tuning, and test for final evaluation.
  3. Preprocessing:
   – For numerical features, apply a quantile transformation (using Scikit-learn’s quantile transformer) for all models except when embedding with PLE, since PLE representations (values in [0, 1]) are shift–scale invariant.
   – For categorical features, use one-hot encoding (unless using CatBoost’s built-in support).
   – Also include experiments where the model is trained with “vanilla” preprocessing versus no preprocessing to evaluate the robustness of PLE.
   – Record the batch size for each dataset (use values reported in Appendix C or as provided by typical Kaggle examples).

B. Training Process and Protocols
  1. Optimization:
   – Use the AdamW optimizer.
   – Loss functions: cross-entropy for classification tasks; Mean Squared Error (MSE) for regression.
  2. Training Strategy:
   – Use early stopping based on validation loss/metric with patience = 16 epochs.
   – Do not use a learning rate schedule.
   – For each tuned configuration, run 15 different random seeds to report mean and standard deviation.
  3. Hyperparameter Tuning:
   – Use Optuna (or a similar Bayesian optimization library) with the Tree-Structured Parzen Estimator algorithm.
   – Search spaces to tune:
    • Output dimension of linear embedding layers (e.g., UniformInt[1,128]).
    • For Quantile-based PLE: number of bins ∼ UniformInt[2, 256].
    • For Target-aware PLE: the maximum number of leaves ∼ UniformInt[2, 256], minimum number of items per leaf ∼ UniformInt[1, 128], and the minimum information gain ∼ LogUniform[1e–9, 0.01].
    • For the Periodic module: number of groups (typically 1 per feature), hyperparameters k (e.g., UniformInt[1,128]) and σ (standard deviation for initialization).
    • For backbone models: number of layers, layer sizes, dropout rates, learning rate (e.g., LogUniform between 1e–5 and 1e–3 or as provided in Table 17 for Transformer).
   – Use the same hyperparameter tuning procedure for all embedding variants to guarantee a fair comparison.
  4. Ensembles:
   – As in the paper, after training 15 models per configuration, split them into 3 ensembles (e.g., groups of 5 models) and average their predictions.
   – Report both single-run and ensemble metrics.

C. Evaluation Metrics
  – For classification tasks: report accuracy.
  – For regression tasks: report Root Mean Squared Error (RMSE).
  – Report mean and standard deviation across 15 seeds.
  – When comparing results (e.g., in tables), consider not only the mean performance but also the variability (standard deviation) as described in the paper.
  – Also measure the number of parameters (model size) to compare overhead introduced by the new embeddings.

D. Additional Ablation Studies and Comparisons
  1. Compare different embedding modules (standard linear, LR, LRLR, PLE variants [quantile-based, target-aware], periodic variants, and even additional alternatives like one–blob encoding as described in subsection 5.2).
  2. Perform experiments that test the sensitivity of deep models to preprocessing – e.g., compare vanilla MLP (which is highly sensitive without proper scaling) versus MLP with PLE.
  3. Evaluate “DL vs GBDT”:
   – Run baseline GBDT models (CatBoost, XGBoost) with the appropriate hyperparameters.
   – Compare rankings as in Table 6.
  4. Replicate the synthetic “GBDT-friendly” experiment:
   – Vary the number of bins for the quantile-based PLE and plot RMSE as in Figure 5.
  5. Record parameter counts and training times to assess overhead.

5. AMBIGUITIES AND POINTS REQUIRING CLARIFICATION

• The exact mathematical formulation of the periodic activation module (Equation 2) is only briefly described. Before finalizing the code, verify:
  – The precise periodic function to use (sin vs. cosine or a variant),
  – The order of operations (whether mixing occurs before or after applying periodic functions),
  – How the trainable coefficient cᵢ is integrated and what dimensions the parameters should have.
• The fusion step for attention-based models (adding a linear layer post-embedding to encode feature indices) should be implemented as described; verify that parameters are not shared across features.
• Some hyperparameter ranges (e.g., the specific distribution for σ in the periodic module) might need fine-tuning in your own experiments. Use the provided distributions (e.g., UniformInt[1,128] for k, LogUniform for minimum information gain) as a starting point.
